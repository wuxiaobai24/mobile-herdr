# 下载停滞与结果反馈修复（beta.11）

用户反馈聊天 APK 链接、项目文件和版本页下载都缺少可判断的反馈。核查发现：聊天 Web 渲染把本机绝对路径当网页地址，原生端不处理本机文件链接；文件传输在全部接收后才弹出保存，只有转圈；版本页只打开 GitHub 发布页。

本轮修复：

- 聊天项目文件链接转为当前 machine / session / pane 的鉴权下载，校验项目目录，保留百分比、大小、取消与结果。项目外路径明确说明，不扩大文件读取权限。
- 项目文件、附件和版本页复用下载逻辑。每30秒无数据进展则报错，可手动重试；校验声明长度，截断响应不能报成功。凭证只在 Header。
- Web 显示“已交给浏览器下载，请查看浏览器下载列表”，不会把开始保存当成已写入磁盘。Android 分块写缓存，区分下载、选择位置与写入；真正写完才显示“文件已保存”，取消则清理临时文件。
- 版本页提供“下载本机 APK”，通过 `/api/android` 鉴权接口获取当前构建；同时保留“打开 APK 发布页”并明确后续由浏览器处理。本机 APK 配套版本、字节数与 SHA-256，构建以原子替换发布文件。

验证：类型检查通过；默认82项通过、6项按环境跳过、566断言；全量 Web 254项通过。新增下载8项连续3次通过，覆盖真实慢速字节流、取消、截断、重试、字节一致性、聊天绝对路径、版本页与320px / 短视口。证据在 `artifacts/download-ui/`，主 Agent 已逐图复看，沿用原主题与动效。

独立签名 release APK 在专用 Android 35 模拟器验证：下载专项8项通过（含4项连接准备与4项下载检查），文件与管理专项17项通过；测试写入仅位于隔离目录与专用模拟器，下载后检查大小与 SHA-256。实体手机输入法、OS保存提供器和厂商后台行为仍待实测。

托管 bridge 已从 beta.10 更新为 beta.11，地址、密钥、Herdr terminal 和存活 native runtime / PID 均保持不变。没有重启用户 Herdr 或 agent。报告：`artifacts/deployment/download-feedback-upgrade.json`。本机实际 APK HTTP 下载已完整校验字节数和 SHA-256。APK仍位于 `artifacts/android/mobile-herdr.apk`；未公开发布。

使用：刷新 Web → 更多 → 版本更新 → 下载本机 APK。下载完成后到浏览器下载列表打开；新 APK 使用原签名升级，Android versionCode 6。
